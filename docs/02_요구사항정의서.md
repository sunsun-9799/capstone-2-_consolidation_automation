# 요구사항 정의서 (3주차)

## 그룹 구조

모회사 1개 + 자회사 2개 (A: 100% 지분, B: 80% 지분). B는 비지배지분(NCI) 계산 대상.

## 계정과목 체계 (간소화, 대분류 수준)

| 구분 | 계정과목 예시 |
| --- | --- |
| 자산 | 현금및현금성자산, 매출채권, 재고자산, 대여금(그룹간), 유형자산 |
| 부채 | 매입채무, 미지급배당금, 차입금 |
| 자본 | 자본금, 이익잉여금, 비지배지분 |
| 손익 | 매출, 매출원가, 판관비, 배당금수익 |

약 15~20개 계정으로 구성. 세부 계정 리스트는 데이터 설계 단계(4주차)에서 확정.

## 기능 요구사항

| 번호 | 요구사항 |
| --- | --- |
| FR-1 | 모회사(100%) + 자회사 2개(A 100%, B 80%) 재무제표를 입력받을 수 있어야 한다 |
| FR-2 | 각 회사 재무제표를 계정과목 기준으로 단순합산할 수 있어야 한다 |
| FR-3 | Trading Partner 필드가 채워진 거래를 내부거래로 자동 식별해야 한다 |
| FR-4 | 그룹 내 매출-매입, 채권-채무를 자동 상계 처리해야 한다 |
| FR-5 | 그룹 내 배당금 지급-수취를 자동 상계 처리해야 한다 |
| FR-6 | 재고자산 내 미실현이익을 마진율 기준으로 계산·제거할 수 있어야 한다 |
| FR-7 | 지분율에 따라 자회사(B) 순이익을 배분하고 비지배지분을 계산해야 한다 |
| FR-8 | 조정 전/후 재무제표와 각 조정 항목의 근거를 함께 출력해야 한다 |
| FR-9 | 내부거래 관련 필수 필드(Trading Partner 등) 누락 여부를 체크할 수 있어야 한다 |

### FR-9 상세 정의 — 내부거래 필드 완결성 체크

- **대상**: 분개 데이터 중 거래유형이 매출/매입/배당/재고인 라인
- **체크 조건**
  - 거래유형이 위 4종 중 하나인데 Trading Partner 필드가 비어있는 경우 → 결함으로 표시
  - Trading Partner가 채워져 있는데 그 값이 지분율 테이블에 없는 회사코드인 경우(오타·존재하지 않는 계열사) → 결함으로 표시
- **출력**: 검증 리포트에 결함 건수, 결함 분개번호 목록, 결함 사유를 표로 표시
- **판정 기준**: 결함 0건이면 "내부거래 필드 완결성: 통과", 1건 이상이면 "확인 필요" 표시

## 데이터 요구사항

| 파일 | 주요 컬럼 |
| --- | --- |
| 재무제표 (회사별) | 회사코드, 계정과목, 금액, 기간 |
| 분개 데이터 | 분개번호, 계정과목, 차대구분, 금액, Trading Partner, 회사코드, 거래일자, 거래유형(매출/매입/배당/재고) |
| 지분율 테이블 | 모회사코드, 자회사코드, 지분율, 취득일 |

내부거래 유형은 매출/매입, 배당금까지 포함하며 이자수익은 제외한다.

## 비기능 요구사항

| 번호 | 요구사항 |
| --- | --- |
| NFR-1 | 자회사 수 확장 시 코드 수정 최소화 (지분율 테이블만 변경으로 대응 가능) |
| NFR-2 | Python(pandas) 기반 계산 로직 + Streamlit 웹 UI |
| NFR-3 | 모든 조정 결과는 추적 가능해야 한다 (어떤 원본 거래에서 왔는지) |
