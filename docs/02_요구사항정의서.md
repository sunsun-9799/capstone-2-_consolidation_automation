# 요구사항 정의서 (3주차, ChatGPT 피드백 반영 개정)

## 그룹 구조

모회사 1개 + 자회사 2개 (A: 100% 지분, B: 80% 지분). B는 비지배지분(NCI) 계산 대상.

## 계정과목 체계 (간소화, 대분류 수준)

| 구분 | 계정과목 예시 |
| --- | --- |
| 자산 | 현금및현금성자산, 매출채권, 재고자산, 대여금(그룹간), 유형자산, 종속기업투자주식, 영업권 |
| 부채 | 매입채무, 미지급배당금, 차입금 |
| 자본 | 자본금, 이익잉여금, 비지배지분 |
| 손익 | 매출, 매출원가, 판관비, 배당금수익 |

약 15~20개 계정으로 구성. 세부 계정 리스트는 데이터 설계 단계(4주차)에서 확정.

## 기능 요구사항

| 번호 | 요구사항 |
| --- | --- |
| FR-1 | 모회사(100%) + 자회사 2개(A 100%, B 80%) 재무제표를 입력받을 수 있어야 한다 |
| FR-2 | 각 회사 재무제표를 계정과목 기준으로 단순합산할 수 있어야 한다 |
| FR-3 | Trading Partner 필드가 채워진 거래를 내부거래로, 비어있는 거래를 외부거래로 자동 식별해야 한다 (거래유형이 매출/매입/배당/재고/대여금인 라인 중 TP 유무로 판별) |
| FR-4 | 그룹 내 매출-매입, 채권-채무를 자동 상계 처리해야 한다 |
| FR-5 | 그룹 내 배당금 지급-수취를 자동 상계 처리해야 한다 |
| FR-6 | 재고자산 내 미실현이익을 마진율 기준으로 계산·제거할 수 있어야 한다 |
| FR-7 | 자회사별 지분율에 따라 지배기업 지분과 비지배지분을 계산하고, 연결재무상태표의 비지배지분과 연결손익계산서의 비지배지분 귀속 당기순이익을 산출해야 한다 |
| FR-8 | 조정 전/후 재무제표와 각 조정 항목의 근거를 함께 출력해야 한다 |
| FR-9 | 내부거래 관련 필수 필드(Trading Partner 등) 누락, Trading Partner가 자기 자신인 경우, 분개번호 중복, 계정과목 마스터에 없는 코드를 체크할 수 있어야 한다 |
| **FR-10** | **모회사의 종속기업투자주식과 자회사의 자본(취득일 자본금·이익잉여금)을 연결조정으로 상호 제거하고, 투자주식이 자회사 순자산 중 지배기업 지분율 해당액을 초과하는 경우 그 차액을 영업권으로 인식해야 한다 (부분영업권법 기준; 전부영업권법·염가매수차익·취득후 공정가치 조정은 범위 외)** |
| **FR-11** | **그룹 내 대여금·차입금 등 내부 채권·채무를 식별하고 상계해야 한다 (이자수익·이자비용 제거는 범위 외)** |

### FR-9 상세 정의 — 내부거래 필드 완결성 체크

- **대상**: 분개 데이터 중 거래유형이 매출/매입/배당/재고인 라인
- **체크 조건**
  - 거래유형이 위 4종 중 하나인데 Trading Partner 필드가 비어있는 경우 → 결함으로 표시
  - Trading Partner가 채워져 있는데 그 값이 지분율 테이블에 없는 회사코드인 경우(오타·존재하지 않는 계열사) → 결함으로 표시
  - Trading Partner가 자기 자신인 경우 → 결함으로 표시
  - 동일 분개번호가 중복된 경우 → 결함으로 표시
  - 계정과목이 계정과목 마스터에 없는 코드인 경우 → 결함으로 표시
- **출력**: 검증 리포트에 결함 건수, 결함 분개번호 목록, 결함 사유를 표로 표시
- **판정 기준**: 결함 0건이면 "내부거래 필드 완결성: 통과", 1건 이상이면 "확인 필요" 표시

## 데이터 요구사항

| 파일 | 주요 컬럼 |
| --- | --- |
| 재무제표 (회사별) | 회사코드, 계정과목, 금액, 기간, 결산일 |
| 분개 데이터 | 분개번호, 계정과목, 차대구분, 금액, Trading Partner, 회사코드, 거래일자, 거래유형 |
| 지분율 테이블 | 모회사코드, 자회사코드, 지분율, 취득일 |

내부거래 유형은 매출/매입, 배당금, 그룹간 대여금·차입금까지 포함하며 이자수익·이자비용은 제외한다.

**거래유형 값 체계**: 내부거래 전용(매출/매입/배당/재고/대여금)과 외부거래용(일반매출/일반매입/판관비)을 분리한다. FR-9의 완결성 체크는 내부거래 전용 거래유형에만 적용되므로, 외부거래(TP 공란)가 같은 라벨을 쓰면 결함으로 오탐된다 — 반드시 별도 라벨을 사용해야 한다.

**부호 처리 규칙**: 분개 데이터는 차변 = +금액, 대변 = −금액으로 표준화한 후 계정별 잔액을 계산한다.

## 비기능 요구사항

| 번호 | 요구사항 |
| --- | --- |
| NFR-1 | 자회사 수 확장 시 코드 수정 최소화 (지분율 테이블만 변경으로 대응 가능) |
| NFR-2 | Python(pandas) 기반 계산 로직 + Streamlit 웹 UI |
| NFR-3 | 모든 연결조정에 고유 Adjustment ID를 부여하고, 원본 분개번호·회사코드·계정과목·조정유형·조정금액을 추적할 수 있어야 한다 |

## 범위 외 (Scope Out)

본 프로젝트는 15주 캡스톤 일정 내에 연결회계 자동화의 핵심 로직을 입증하는 것을 목표로 한다. 이에 따라 아래 항목은 구현 범위에서 명시적으로 제외한다.

- 해외 자회사 통화환산
- 전부영업권법(비지배지분의 공정가치 측정), 염가매수차익, 영업권 손상평가
- 취득일 공정가치 조정(순자산 재평가)
- 단계적 취득
- 종속기업 처분
- 지분율 변동
- 내부거래 이자(이자수익·이자비용)
- 법인세 효과
- 복잡한 파생상품
- 다중 통화 연결
